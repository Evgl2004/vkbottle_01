# VK-бот на `vkbottle` + `PostgreSQL` + `Redis`

## 1. Назначение проекта

Этот репозиторий содержит разработку чат-бота для мессенджера ВКонтакте.
За функциональную основу взят Telegram-бот из репозитория:

- [Evgl2004/aiogram_bot_01](https://github.com/Evgl2004/aiogram_bot_01)

Текущая цель проекта:

1. Перенести ключевую бизнес-логику из Telegram в VK.
2. Сохранить структуру данных и сценарии поведения пользователей.
3. Построить MVP с обязательными модулями:
   - регистрация пользователя;
   - обработка legacy-пользователей;
   - система обращений (тикеты);
   - модерация тикетов;
   - интеграция с iiko;
   - хранение состояния диалогов в Redis;
   - хранение бизнес-данных в PostgreSQL.

## 2. Технологический стек

- Python 3.x
- `vkbottle` (транспортный слой VK)
- `SQLAlchemy` + `asyncpg` (асинхронный доступ к PostgreSQL)
- `redis` (FSM/состояния диалога)
- `pydantic` / `pydantic-settings` (конфигурация)
- `loguru` (логирование)

## 3. Ветки и процесс разработки

- `main`:
  - базовая инициализация проекта;
  - стартовая структура и документация.
- `codex/develop-cai`:
  - активная функциональная разработка.

Важное правило:

- Коммиты выполняются после каждого логически завершенного этапа.
- Сообщения коммитов оформляются подробно и на русском языке.

## 5. Быстрый запуск (локально)

### 5.1 Подготовка `.env`

Скопируйте шаблон:

```bash
cp .env.example .env
```

Заполните обязательные переменные:

- `VK_BOT_TOKEN`
- `POSTGRES_PASSWORD`
- `ADMIN_USER_IDS` (опционально, но желательно для модерации/админ-доступа)

Для расширенного тестового логирования рекомендуем:

- `LOG_LEVEL=DEBUG`
- `LOG_SUPER_VERBOSE=false` (по умолчанию):
  - `false` — подробный DEBUG уровня приложения без шумных внутренних логов `vkbottle`;
  - `true` — максимально подробный режим расследования (включая низкоуровневые транспортные логи).

### 5.2 Запуск через Docker

```bash
docker compose up --build
```

Контейнеры:

- `bot`
- `postgres`
- `redis`

## 8. Подтверждение телефона через VK Mini App

В проекте реализован сценарий подтверждения номера телефона через VK Mini App. Это позволяет пользователю подтвердить телефон безопасно, без ручного ввода в чат.

### Архитектура

1. **Бот предлагает выбор способа подтверждения**: ручной ввод или через Mini App.
2. **При выборе Mini App** бот генерирует ссылку на мини-приложение с одноразовым токеном состояния (`state_token`).
3. **Пользователь открывает Mini App** в интерфейсе VK, нажимает кнопку «Подтвердить телефон», и VK передаёт номер телефона в зашифрованном виде.
4. **Mini App отправляет данные** на backend-эндпоинт `/api/v1/phone/verify`.
5. **Backend проверяет подпись VK**, валидирует телефон, сохраняет его в профиль пользователя и устанавливает флаг подтверждения.
6. **Бот обнаруживает флаг** и продолжает сценарий регистрации.

### Настройка Mini App

Для работы сценария необходимо:

1. **Создать мини-приложение** в [панели разработчика VK](https://vk.com/apps?act=manage).
2. **Заполнить настройки**:
   - Получить `ID приложения` (числовой) и указать его в `VK_MINI_APP_ID`.
   - Сгенерировать `Защищённый ключ` (секрет) и указать его в `VK_MINI_APP_SECRET`.
   - Настроить `Адрес мини-приложения` (URL). Если используется стандартный домен VK, оставьте `https://vk.com/app` (код автоматически добавит ID). Если используется кастомный домен, укажите полный URL в `VK_MINI_APP_URL`.
   #### Детальное пояснение по `VK_MINI_APP_URL`

   Переменная `VK_MINI_APP_URL` определяет базовый URL, по которому будет открываться ваше мини-приложение. В зависимости от того, где размещено мини-приложение, значение может быть разным.

   **1. Стандартный домен VK (рекомендуется для начала)**

   Если вы создали мини-приложение через панель разработчика VK и не настраивали кастомный домен, то ваше приложение доступно по URL вида:
   ```
   https://vk.com/app{APP_ID}
   ```
   где `{APP_ID}` — числовой идентификатор приложения (например, `1234567`).

   В этом случае в `.env` нужно указать:
   ```
   VK_MINI_APP_URL=https://vk.com/app
   ```
   **Важно:** не добавляйте `APP_ID` в URL, потому что код автоматически подставит его из `VK_MINI_APP_ID`. Функция `generate_mini_app_link` проверит, что если `VK_MINI_APP_URL` равен `https://vk.com/app`, то она добавит `APP_ID` к ссылке. Это сделано для удобства, чтобы вам не приходилось менять URL при смене `APP_ID`.

   **2. Кастомный домен (ваш собственный сервер)**

   Если вы разместили мини-приложение на своём домене (например, `https://myapp.example.com`), то в `VK_MINI_APP_URL` нужно указать полный базовый URL **без добавления `APP_ID`**. Например:
   ```
   VK_MINI_APP_URL=https://myapp.example.com
   ```
   Код не будет добавлять к этому URL никаких суффиксов, а просто прикрепит query-параметры (`?vk_user_id=...&state_token=...`).

   **3. Локальная разработка**

   При локальной разработке мини-приложения вы можете использовать локальный сервер (например, `http://localhost:3000`). В этом случае укажите:
   ```
   VK_MINI_APP_URL=http://localhost:3000
   ```
   Убедитесь, что бот может открыть этот URL у пользователя (пользователь должен иметь доступ к localhost, что невозможно, если бот работает на сервере). Поэтому для продакшена используйте публичный домен.

   **Как проверить, что URL настроен правильно?**

   - Запустите бота и перейдите в сценарий подтверждения телефона.
   - Бот отправит вам ссылку, сгенерированную функцией `generate_mini_app_link`.
   - Откройте эту ссылку в браузере (или в мобильном приложении VK) и убедитесь, что она ведёт на ваше мини-приложение.

   **Примеры итоговых ссылок:**

   - При `VK_MINI_APP_ID=1234567`, `VK_MINI_APP_URL=https://vk.com/app`, `user_id=100500`:
     ```
     https://vk.com/app1234567?vk_user_id=100500
     ```
   - При `VK_MINI_APP_URL=https://myapp.example.com`, `user_id=100500`:
     ```
     https://myapp.example.com?vk_user_id=100500
     ```

   Если вы не уверены, какой URL использовать, оставьте значение по умолчанию `https://vk.com/app` и укажите правильный `VK_MINI_APP_ID`. Этого достаточно для работы сценария через стандартный домен VK.
3. **Включить веб-сервер** в настройках бота (`WEB_ENABLED=true`) и убедиться, что порт `WEB_PORT` доступен извне (если Mini App работает на внешнем хосте).

### Переменные окружения

Добавьте в `.env` следующие переменные (примеры в `.env.example`):

```
VK_MINI_APP_ID=1234567
VK_MINI_APP_SECRET=your_secret_key_here
VK_MINI_APP_URL=https://vk.com/app
WEB_ENABLED=true
WEB_HOST=0.0.0.0
WEB_PORT=8080
```

### Безопасность

- Все запросы от Mini App подписываются секретным ключом; backend проверяет подпись перед обработкой.
- Одноразовые токены состояния (`state_token`) хранятся в Redis с TTL 5 минут и удаляются после использования.
- Телефон нормализуется и валидируется перед сохранением.
- Обработаны негативные сценарии: отказ пользователя, невалидная подпись, истёкший токен, повторное подтверждение.
